# Contributing

Thanks for considering a contribution. This repository is Marcus Baw's maintained set of engineering defaults, so proposed changes need clear evidence and a practical consumer.

## Before You Start

Search existing issues and pull requests before opening a new one. Discuss non-trivial changes before writing substantial prose or code. Standards should describe patterns proven in real projects, not hypothetical preferences.

## Pull Requests

1. Create a descriptive branch from `main`.
2. Keep the pull request focused on one coherent change.
3. State the evidence for the proposed rule: a real implementation, authoritative source, test, measurement, or user feedback.
4. Distinguish a reusable standard from a project-specific exception.
5. Update examples and cross-references when they are affected.
6. Run the documented validation checks before pushing.
7. Explain the change and its rationale in the pull request description.

## Direction

The maintainer has final responsibility for scope and design decisions. Constructive disagreement is welcome. Organisation-specific users may copy these standards and maintain their own variants where their context requires it.
